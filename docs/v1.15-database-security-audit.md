# V1.15 database security and migration hygiene

## Scope
This branch contains a narrowly scoped database migration. It has **not** been applied to production.

## Changes proposed
- Add five indexes for foreign keys flagged by Supabase Performance Advisor: `in_app_notifications(application_id)`, `job_messages(application_id)`, `job_messages(candidate_id)`, `job_messages(poster_id)`, and `job_messages(sender_id)`.
- Rewrite the `job_messages` SELECT and INSERT policies to wrap `auth.uid()` in scalar SELECTs. The predicates were compared with the live policy definitions and retain the same participant, sender, recipient, application, job, and poster-ownership checks.

## Production metadata used for the free test fixture
The disposable GitHub Actions PostgreSQL fixture was updated from read-only production metadata. It mirrors the columns, nullability/defaults, and relevant primary/foreign-key/check constraints for `profiles`, `companies`, `jobs`, `applications`, `in_app_notifications`, and `job_messages`, including the `auth.users` UUID references used by message participants. The fixture now runs PostgreSQL 17, matching the production major version.

This is a **schema-faithful test slice**, not a full database clone: it does not reproduce every table, trigger, extension, Supabase Auth implementation detail, or unrelated RLS policy. No production data is copied.

## Validation performed
- PostgreSQL 17 disposable smoke test applies the migration and asserts all five indexes and the expected SELECT/INSERT policies, while confirming the existing UPDATE policy remains.
- Behavioral RLS test covers candidate, company owner, individual poster, outsider denial, sender spoofing rejection, and recipient read-state update.
- Vercel preview check completed successfully; no frontend/application source files are changed in this PR.
- The production SELECT/INSERT policy definitions were inspected read-only and compared with the proposed predicates.

## Remaining limitations before applying the migration to production
- No paid Supabase development branch was created; no credit was available. GitHub Actions is the zero-cost isolated test environment.
- The complete production schema and Supabase-managed Auth environment have not been cloned, so this test does not replace a full Supabase branch validation.
- The production migration ledger has 26 applied entries while the repository tracks 20 migration files. Historical migration drift remains unresolved. Do not mark historical migrations applied, invent replacement SQL, or run a blind full replay.
- Admin dashboard, hiring finalization, and company-description RPC end-to-end flows are unchanged by this migration and have not been re-exercised as part of V1.15.

## Findings deliberately not changed
- `public.admin_users` and `public.push_notification_events` have RLS enabled with no client policies. This denies direct client access and is intentional.
- `is_admin`, `finalize_job_hiring`, `update_individual_job_application_status`, and `update_owned_company_description` are SECURITY DEFINER functions. Read-only inspection confirmed execution is granted to `authenticated`, not `anon` or `PUBLIC`. Their definitions and grants are not changed.
- Leaked-password protection is an Auth dashboard/plan capability, not a SQL migration.
- `pg_net` remains in its current schema because scheduled alert routines use `net.*`; moving it needs a separate coordinated change.
- The Performance Advisor also reports a duplicate unique index on `applications`. It is outside this migration and should be evaluated separately before any index removal.

## Production safety
Merging this PR only adds the reviewed SQL migration and test/documentation files to GitHub. It does **not** execute the SQL against Supabase. Do not apply the migration to production until the migration-ledger drift and full-schema validation have been resolved.
